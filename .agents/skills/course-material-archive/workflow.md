## 本地教材工作流

下列命令均从 Worldanalysis 根运行，使用脚本回报的实际课程包路径。完整参数、目录与数据结构见[开发文档](../../../docs/课程资料整理与%20Obsidian%20教材制作手册.md)。

接到整批目录时，用 `course.ps1 batch plan "<原件总目录>"` 查看自然顺序。已有批次先从 `batch status` 取得当前项目、课程包和不同验收/待补顺位，按原件身份续作。完成收到范围的日常库同版验收后执行 `batch finish`，按真实范围状态退出当前顺位并继续下一项。不能因一项仍有缺件挂起整批。

### 先判定收到范围，再决定出版状态

1. 每个项目先盘点所有已收到的原件，包括音频、视频、档内教学、文档正文及附件。把实际教学内容与推广、指引、参考素材、重复件区分开。
2. 对未取得的原件逐项定义缺口：具体材料、核心或非核心、来自哪个已核实原件/时码或实际目录、对完整课程/跟做的影响、取得/确认条件。核心包括独立讲次、未演示的教学步骤和不可替代的课程配套；非核心包括不含新增教学的独立案例原素材、支持、可选练习及附加福利。不能凭数量或文件后缀认定核心完整；作者渠道的实际可知部分必须核入正文，尚未知部分如实记录。宣传收益没有额外凭证时只写为讲师主张和验证边界，不要求为讲师实现或验证收益。
3. 完整分析收到的所有实质教学原件，缺未收到的独立外部内容也不中断取材。仅指引、没有可读独立教学内容时只做来源盘点、状态登记及缺件记录，进入下一项。
4. 经过同版双向核对、独立事实核验和阅读验收后，按实际状态发布：`完整验收`（本次范围已确认齐全）、`配套待补`（未收到的非核心配套，现有实质教学已全核）、`核心待补`（有明确核心缺口，仅验收当前所收教学范围）。每种状态的一篇同名教材都必须明示范围与缺口。已收到而未核、漏写、不读、误读或无法回源的材料不属于外部缺件，继续阻塞该稿。
5. 再次收到原件时以同一课程身份恢复，在同一篇笔记增加内容并重新绑定验收和阅读回执。不重复出稿、不将旧签收假装为新版完整范围。待补、同源复用与留档分别登记，扫描新来件继续。

1. **入库并复用可用成果。** 执行 `course.ps1 start "<原件文件夹>"`，用 `.course/ledger` 的原件、媒体和附件清单确认范围。复核旧课时先拿用户给的完整来源目录对照旧入库清单，再核新增文件的开头、授课目录、结束话语与相邻片段。录制切分重叠时把两个原件和实际重叠时间登记，重复内容在正文讲一次。缺少同课依据的文件保留待判。依原课顺序校对 `讲次顺序.json`。`媒体设置.json` 可指定语言、音轨、原字幕与同版有声件。原件和配置未变时用 `prepare` 恢复处理。原视频探测失败时先完成其他文件，按 `status` 提示保留缺口并核对可读原件或恢复副本。若可用字幕只概括了操作，保留它并对照全音轨转写和区间内文本差异。

   查看媒体归类、父附件和成员来源。先确认压缩包和幻灯片中的媒体是否是教学、参考素材或重复版本。独立录音也要确认用途。教学文件按原课程顺序转写和核画面。归属未定时读取候选的本地证据，再在 `媒体归类.json` 记录理由。外链和讲义提过但未随附的文件保留查证记录。

   本批其他目录可能留有同课的完整版本。用课程目录、共有原片的时长和多个位置的音画确认归属，并逐件检查它独有的附件。把有依据的新增原件和当前全部入库原件复制到独立本地目录，保留相对路径和文件指纹，登记新增件的实际来源，再用 `start` 建立新课程包。用 `batch supplement <清单> <顺位> <新课程包> --reason <原件核对依据>` 延续原项目。校对 `讲次顺序.json`，按保留的原件身份继续复用已有取材。无需等全部未知缺件到齐才开始或恢复已有材料分析。其它目录保留其原队列位置。

   容器能打开但选定音轨解码失败时，`prepare` 保留该集可读画面及原字幕，记录音轨失败和已解出的样本时长，继续处理其他集。用 `status` 查看受影响的源文件和探测窗口，然后回到原始音轨查实际损坏时码。恢复只从原始字节或经验证的同源副本取用。在 `媒体设置.json` 的该集下用 `recovery` 指向恢复清单。用可读音轨替换时，确认原画及音画时间轴一致，按原时间保留无法恢复的区间。回放到尾，核对画面、音轨长度与教材影响，保留原件和工作副本的摘要。
2. **取材到片尾。** 逐集核实原片音轨及实际解码范围。有声原片转写全轨并保留原字幕。从容器开头直接解码，区间起点晚于开头时才定位。抽查片头与片尾，把独立解码的 PCM 与正式采用的范围对照。无音轨时记录实际情况，同版有声补录要先核对画面、时码与覆盖。用 `read <课程包> <讲号> --start <秒> --end <秒>` 取时间窗。对数字、否定、短指令、专有词、分块交界或缺失语音回到原音，必要时指定 `refine --lesson <讲号> --range <起秒> <止秒>`。保留原版本和复识输出，有原件依据才用 `adopt` 改 `采用转写`。参考声轨只有一段时按片段继续视觉取材。音频候选及阈值以下区间仍需结合内容判断。
   GPU 长轨从同一条连续 PCM 流按样本分块。复核正式窗口能首尾接续，汇总实际样本数与独立整轨解码相符。中断后再次从原音轨头解码，复用同一版本已完成窗口的转写。
   新的 GPU 全轨取材可使用 G 盘共享 ASR 精确缓存。每个窗口仍完整解码，验证音源指纹、实际 PCM SHA-256、声轨、时码范围、语言、模型及运行器、FFmpeg 和取材配置。仅这些一致且缓存内容指纹有效时复用自动识别结果；`asr_exact_cache` 登记本讲命中及实际识别的窗口数。已有项目的旧窗口记录仍用于本项目续作，不自动提升为跨课缓存。采用稿、课序、附件、作者及发布回执继续分别核对。缓存位于课程运行目录 `cache/course-asr-exact`，只保存自动识别的短文本和区间，不复制原片或 PCM。如需关闭跨课缓存，在课程入口环境设置 `WORLDANALYSIS_ASR_EXACT_CACHE=0`。
3. **核视觉与附件。** 对讲解与界面互补、无声、硬字幕、暗色画面分别选时段。把人声活动标出的 `outside_speech` 画面候选与原片对照，留意长转写区间内部的静默操作。短暂菜单、光标圈点和前后状态用 `window` 回查。长时间同屏用 `observe` 按原始时间排序打开局部图，硬字幕可裁字幕带加 `--ocr`，逐项核 OCR 的时码、小字和数字。纯画面只讲能看到的动作和产物。PDF 按页保留原生文字和原图。含截图的页同时查整页渲染及 OCR，核对画面内的按钮、参数、标注意图与作者线索。表格查原单元格、嵌图和公式。PPTX 的文字、形状、截图共同提供信息时查看完整渲染页。对附件提取缺口逐件记录原件、实际查看部位、有无新增教学以及缺失时的原因。先看原片或附件页图，再以 `keep` 登记原像素。整理示意图标明身份。
   遇到「截图保存」「提示词放在画面」和类似提醒，从提示前查到页面切走。用 `window` 连续解码，必要时用 `observe --ocr` 核小字和一闪而过的表格。逐项读出只在画面里出现的指令、规则、参数和作者入口，把原文要点和原图放到对应讲解。角标挡住的内容记下具体位置，能见部分继续使用。
   「关注一下我的公众号」「在原视频底下留言领模板」一类口述在未读出具体账号时也进入复核。沿提示时间回看名片、连续画面和随课文件，确认公开渠道的全名、用途和资料是否实际随包。把课程作者的教学入口在正文讲清楚，出处跟着同段。

4. **先列来源要点，再写一篇教材。** 用 `coverage <课程包> --write` 建立独立原件核查范围，逐个查课程片段、附件页或档内成员、片头片尾和画面署名。基于实际片段和附件定位，在 `.course/work/逐段要点/<讲号>.json` 记录概念、输入、动作、条件、参数、原例、纠错、结果和关系。按来源独立排查行业逻辑、盈利来源、执行失败和课后问答，再对照旧稿去重和补缺，旧索引只作查找入口。每条参数保留案例、分母、时间窗和前后条件，教师估算或主张用原身份写。外部核验、编辑解释和自拟练习注明身份。写 `.course/work/教材.md`，教学音视频按讲次落到二级标题，在动作旁放能支持它的原图或注明身份的示意。
   每项随课文件先看内部结构及用途。核查未在口播出现的模板、练习和规则，保留工作簿、导图和压缩包中可编辑的原件入口。RAR 和 7z 的成员列表、原始路径和逐件提取结果在该附件的资料记录里。对照留存的成员读图、表和文字，检查仍有缺口的成员。对联系人结合自我介绍、片头片尾、原始署名或名片判定。其他课程同指纹的站务说明有助于识别分发方。同一账号合并其多处证据，明示用途及来源。把已查到的文件位置、原片时码、归属和未决项写进验收记录。

   旧版 Word 的 `coverage` 提取项包括正文和独立的内嵌图。原图即使没有在文本中留下对象占位，也回头核对其中的界面参数、示例账号、圈点和规则。相同图片可排一次，原文档中的重复位置仍登记。按实际内容区分讲师渠道、样例主页和平台入口。

   自动候选为空时也回看原始画面。遇到移动或斜放的联系方式，在片头、片中和片尾选不同位置的清晰帧核对原文及用途，留存能读完整标识的一帧。已确认的微信号、作者账号或网址写入 `findings[].value`，在对应正文段落保留原值，并附同一位置的隐藏出处。

   PDF 的隐式链接在每个原页的 `pdf_hyperlinks` 中登记目标和矩形位置。结合可见的链接文字、签名与周边段落确认用途，再检查正常可访的范围。原生提取可能只读到分发页脚或裁边外旧图层，仍要逐页读原图。截图中的仓库链接即使无「作者」等标签也要核查。遇跨行网址用完整原字核对；只有截断片段时，查同一文件的完整账号与对应公开项目，留清楚核实依据。原包讲法和作者后来更新的用法各自按版本呈现。

   HTML 附件先提取静态正文、表行和原链接，按段落行号及章节标识回查。对动态区域和嵌入图音视频另外核对原始对象。软件项目只收到安装件时，登记原包成员并核对作者发布件的版本和文件指纹。用匹配安装封装版本的离线读取工具检查嵌入手册、配置示例及截图，保留成员路径与指纹。需要补原作者资料时，按对应版本保存文档和画面，保留出处，并注明是另核的作者资料。

   只收到分享链接时，用原件提供的提取信息检查原入口。能看到目录时记录文件、层级和大小，并区分目录可见与原文件已到本地。文件可正常取得后按原目录入库。需要账户或仍拿不到原件时，在原顺位留存具体缺口与复查点；若本地还有实质教学原件，则按收到范围继续取材和编写，不等待该指引变为可访问。作者公开资料可补充核验课程身份、帮助入口和不同版本，教材内容仍由实际得到的原件支持。
5. **预览和逐集复核。** 用 `preview` 生成当前稿和同版填写模板。把独立核查过的内容与实际缺口写入 `验收记录.json`。逐项找到应讲内容在正文中的位置，再反向查每段正文的引用、案例条件和身份。用 `check-review` 提前检查覆盖情况。补齐缺项后用 `accept` 完成内容、原图和隔离 Obsidian 阅读检查。
6. **更新日常 Obsidian。** 确认正在使用的库、同课原目录和已有编辑。首次用 `deliver` 迁移或建立 `课件/<项目名>.md` 并返回直达链接，已绑定的课程由 `accept` 更新。确认课程资料仍按约定留在本地。用 `verify-reader` 重开该入口的同路径同版副本，核全部章节、步骤旁的图片、隐藏出处与折叠到页尾，再跑 `verify --require-vault`。中断需分别保存已完成的课程包版本和日常库核验进度。

### 本地教材编写提示

> 先确定学习者这一节要解决什么问题。理论讲依据、原因和边界，案例把背景、选择和结果连起来，公式用变量、单位、算式和演算展开，操作把入口、状态、动作及结果连起来。讲师的亲历明确归给讲师，课堂原话可具名引用；学习者的动作直接引导，自拟输入和产物标为「演算示例」或「练习」。多个来源说明同一问题时合并讲解，新增的条件、分支、数字和失败经验保留。影响使用的限制留在相关段落，拼接、校对和取图记录留在工作区。
>
> 用 `{{02|03:15–03:42}}` 记录稳定原片编号与文件内时间，用 `{{D003|Sheet1 C4:O6}}` 记录附件位置。发布时段落出处、配图出处和文末索引使用同一阅读讲次，并保持原片时间不变。紧贴动作下一段用 `{{img:原图文件名去后缀|550}}` 插图，说明图帮助找到的入口、核对的状态或解释的关系。同一动作反复出现时留最能说明它的一张，界面近似但光标位置、选项或结果有教学差异时保留各自画面。原片字幕能支持术语或数值，界面原图才用于确认控件。正文连续呈现，原件入口默认在文末收起。
