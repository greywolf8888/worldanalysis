# 本地课程教材制作

## 已有本地课程文件夹

按[项目规则](../../../AGENTS.md)在 Worldanalysis 根运行 `_tools/course_production/course.ps1 start "<原件文件夹>"`，以命令返回的课程包为续作入口。已有包用 `status`、`prepare` 和已有验收记录接续。更新旧课时先核完整原件与原入口，对得上的证据可以复用。长课先用实际原片完成一讲的取材、编写和阅读验证，再推广到其余视频。详见[本地教材工作流](workflow.md#本地教材工作流)。

有多个项目时先用 `batch plan` 查看目录，再用 `batch init` 建立独立批次状态。按自然顺序绑定当前项目和课程包，用 `batch status` 获取续作点。原件待补时登记具体缺口并保留顺位。已完成的项目用现行脚本核验日常库后再用 `batch finish` 登记。

每项目发布一篇 Markdown，沿用日常库项目目录，入口用项目名 `课件/<项目名>.md`。保留原课讲次和必要的先后关系，讲内按学习问题组织。直接解释方法，操作自然面向学习者，讲师亲历和课堂主张明确归给讲师，需要保留原话时用引述，新增计算标为演算示例。正文给足准备、入口、参数、案例、纠错和结果。对有声原片完整解码转写，另外核查短暂菜单、同屏圈点和无口播操作。去除重复图，保留能说明不同动作或状态的图并紧贴相应段落。出处、转写复核与分卷记录默认留在隐藏注释或工作区。

先用 `coverage` 从当前原件和取材记录生成核查范围，再从 `read` 的采用转写出发逐段对照原片和附件。独立记下来源要点、附件实际位置和作者线索。用 `observe` 查看短动作、字幕和暗界面，用 `refine` 复识争议，用 `adopt` 纳入已经核实的结果。写稿后完成来源到正文、正文到来源的两次核对，按[本地教材验收](acceptance.md#本地教材验收)填写同版内容记录。用 `accept` 审核课程包，用 `deliver` 更新日常库并取得 Obsidian 直达链接。用 `verify-reader` 重开日常入口的同路径同版副本，核阅所有章节、邻图和页尾。用 `verify --require-vault` 核验交付。命令、字段和恢复方式见[开发文档](../../../docs/课程资料整理与%20Obsidian%20教材制作手册.md)。

独立检查口播之外的随课资料和开头、片尾、界面角落。把模板、规则、练习及经原件追溯的资源与作者支持写在相关段落或同一篇的配套资料节。二维码及账户署名先核发布者及用途。分发方推广和归属未明的渠道按查到的证据登记。

核对 `status` 的媒体归类和缺口。教学录音单独转写。幻灯片或归档内教学录像像散装原片一样解码、检查界面和选图。父附件仍逐页或逐成员核对，出处指回具体页或档内路径。样片、配乐、软件资产及同版副本按原件事实归类。完全相同的文件可以共用取材，画面或音轨近似时先确认该版是否有独立教学内容。

遇到标题、扩展名和内容不一致的附件，先看原件内容再决定怎么用。带 `.srt` 后缀的字幕写作指南完整按说明文档读，保留其示例与适用条件。

遇到不可读原视频，`status` 可查看待补原件，其他视频照常提取和校对。保留原始文件，在单独副本上核查恢复。确认其来源和可用范围后，按开发手册登记恢复文件，在相关讲次说明原画、音轨和时间的核查范围。识别器明确报某个已解码窗口没有语音时，查看人声检测及画面变化再决定教材保留的操作。
