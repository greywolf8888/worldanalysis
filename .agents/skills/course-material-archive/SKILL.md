# 本地课程教材制作

执行前读取 `AGENTS.md` 和 `整理结果/生产控制/当前接力.md`。主控、分析和测试使用工作区内的独立目录；当前项目收到范围全部核验、同版阅读并按实际状态登记后，即重新扫描全分类，默认新增且有实质原件就绪项目优先于已有积压，除非用户明确指定顺序。分类本身、分析结果、测试稿件与临时目录不作为项目。升级收尾后持续目标仅在指定分析聊天，测试按实际需求运行，停止无效开发。

## 从本地原件开始

从课程工作树运行 `_tools/course_production/course.ps1 start "<原件文件夹>"`，以输出的课程包路径接续。已有包先看 `status`，按需用 `prepare` 补取材。长课先完整跑通一讲的取材、编写和阅读验证，再处理其余讲次。整目录从 `batch plan` 或现有 `batch status` 开始，待补原件留在原顺位。

## 取材、编写和验收

- 写稿前用 `coverage` 建立独立范围。逐集检查原音、字幕和画面，逐件检查附件内部结构与作者渠道。遇到讲师邀请关注频道、留言或找课程负责人领资料，回看相邻原画、名片和附件，核清公开或课内入口、适用学员及资料是否随包。附件截图里换行或截断的项目链接，回到原页和署名复核，再核对同一作者的公开仓库及版本。把独立音频、档内录像和幻灯片内嵌视频纳入核对。先核实同版或重复关系，再复用取材。无法解码时保留原件、登记故障，继续处理可读材料。详见[工作流](workflow.md#本地教材工作流)。
- 有声件核对实际解码的起止和长轨分段相接的样本。从容器开头连续解码，分块交给模型。抽查第一句、最后一句和分块处的已采用转写。
- 遇到缺讲、缺文件或编号不连续，先在获授权的本地来源中查同课版本。核对共有原片的音画、时长和讲次关系。确认同课的新增原件按工作流建立补料包，从当前顺位继续验收。把未收到的核心讲次/教学配套与非核心外部参考、练习、支持和未证宣传结果分级记录，均不停止已收到原件的取材和编写。全部收到的教学原件仍须完整通过双向核对和独立事实、阅读验收。非核心外部缺件按「配套待补」发布，核心实质未到按「核心待补」发布收到范围版，不冒充整课；原件、范围、缺项和收录状态都可追溯。只有指引、没有独立实质教学内容不造教材，登记后接续下一项。
- 逐集查教师提示截图、保存、看屏幕前后的短时画面。只显示在画面里的指令、规则和补充讲义也进入取材，核对原字与页面位置。
- PDF 中的按钮、参数和署名用原页或局部放大图核实。检查按页登记的链接注释，把同一地址的多处点击区域合并成一个阅读入口。
- 写成一篇可跟做的教材。操作面向学习者，讲师亲历具名，新增演算标明示例。关键图贴对应动作，文末收起原课和资料链接。逐条核对原件是否写进正文，再逐段反查正文出处、案例条件与结论。发现缺项先补查并修正文。
- 用 `preview` 生成同版模板，按[验收说明](acceptance.md#本地教材验收)填写后运行 `accept`。首次绑定用 `deliver`，已有绑定由 `accept` 更新。用 `verify-reader` 重开原入口同版读到文末，再运行 `verify --require-vault`。详细参数见[开发手册](../../../docs/课程资料整理与%20Obsidian%20教材制作手册.md)。
- 发布时同步刷新日常库的 `00 入口/00 项目总览.md`，入口按 Obsidian 名称升序排列。同名正文、验收范围与具体缺口同步展示，完整验收、配套待补、核心待补和历史版本明确区分。不将同源复用、留档或真正待原件计入新教材；补件更新原入口。
