# Obsidian 呈现设计：从正式证据到可阅读课程

日期：2026-11-15

## 1. 目标与本轮边界

Worldanalysis 负责采集、证据发布、完整性检查、任务状态和分析；Obsidian 负责阅读、检索、个人笔记和资料关系整理。用户允许读取完整媒体时间轴，但不希望在本地生成完整视频或完整音频文件，最终主要保留文字、真实关键帧和必要的小型来源索引。

本轮首版的实现目标是 **把 Worldanalysis 已正式发布的本地 Bundle 导出成可供 Obsidian 阅读的 Markdown 与图片**。它是呈现出口，不是新采集器，不会因导出成功而改变后端采集、阅读或分析状态。

本文件给出产品设计与后续能力边界；没有在用户电脑安装 Obsidian、登录百度网盘或验证完整课程。本文的页面结构、字段和命令交互是设计建议，实际首版支持范围以本轮代码、命令帮助和验证记录为准。

| 能力 | 本轮定位 |
| --- | --- |
| 已发布 Bundle → 本地 Markdown、图片、缺口说明 | 首版导出目标 |
| 不安装第三方插件即可阅读本地资料 | 首版呈现目标，仍需 Obsidian 实际打开检查 |
| 重复导出与人工修改保护 | 首版需重点核验，不能凭文档宣称通过 |
| 从百度页面取得字幕、笔记和图片 | 独立采集桥接工作，不由 Vault 导出自动获得 |
| 无现成资料时，顺序流式转写与抽帧 | 独立媒体输入工作，尚不能据呈现结果宣布实现 |
| 任意笔记改名、移动后自动追踪 | 后续能力，不能假定现有导出器已经支持 |
| 用户校订全文反向写回证据与任务状态 | 后续设计，首版不提供全面双向同步 |
| Bases、Canvas、自定义 Obsidian 插件 | 可选增强，不作为第一份可读材料的前置条件 |

## 2. 为什么先采用普通 Vault

Obsidian 的 Vault 就是本地文件夹及其子目录，笔记以 Markdown 文本保存。官方说明外部文件变化会自动反映到 Vault。因此，Worldanalysis 可以直接输出普通文件，用户用 Obsidian 打开该目录即可阅读，无需为展示重新开发一套应用或数据库。

依据：[How Obsidian stores data](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data)。

图片也是普通本地附件，可以直接写入 Vault，再由笔记内嵌显示。导出时应采用 Vault 内的相对路径；不要依赖另一个电脑不存在的绝对路径，也不要仅保留可能失效的远程图片网址。

依据：[Attachments](https://help.obsidian.md/attachments)、[Embed files](https://help.obsidian.md/embeds)。

呈现层可生成文字和图片的派生副本，但正式 Bundle 与现有 SQLite 台账继续作为权威记录。不要为了让 Obsidian 阅读而修改不可变证据，也不要把原始媒体复制到 Vault。

## 3. 页面内容与用户路径

### 3.1 课程总览

打开课程后先看到资料清单和可用程度：资料标题、文字状态、画面状态、仍有缺口的原因，以及进入单视频资料的链接。若当前 Bundle 含多种文件，按真实来源分组；不能只因项目名称是课程，就把所有资料标成视频。

课程总览应直接显示“部分完成”等真实状态。用户无需进入日志才能知道哪些材料尚未取得。展示层不以文件个数、图片个数或最后一个字幕时间戳推导“整课完成”。

### 3.2 单视频资料

建议正文顺序：

1. 标题、来源页面、视频时长，以及文字和画面的实际状态。
2. 可用的带时间戳全文；缺失范围或无时间信息应直接注明。
3. 按时间组织的真实帧图与必要 OCR。
4. 平台笔记及其附图，保持独立来源标识。
5. 已发布分析报告的链接或清晰标注的派生分析。
6. 用户个人笔记的入口。

AI 摘要不能替代全文。平台笔记中的图片在未核实前应标成“平台附图”，不能自动升级成“真实关键帧”。图片文字描述不能代替图片本身。若一个 Bundle 没有足够元数据区分这些来源，呈现应写“来源待核验”，不猜测。

### 3.3 建议文件角色

以下是产品角色，不要求为符合名称而改造既有存储：

| 角色 | 示例 | 更新原则 |
| --- | --- | --- |
| 课程入口 | `课程总览.md` | 程序生成，更新前检查用户修改 |
| 机器整理的资料 | `视频ID/资料.md` | 对应已发布证据版本，保留来源和缺口 |
| 个人笔记 | `视频ID/我的笔记.md` | 首次创建后由用户维护，不自动覆写 |
| 本地图像 | `视频ID/images/` | 用稳定身份或内容哈希命名，复用相同字节 |
| 导出索引 | 小型 JSON | 记录 Bundle 身份、导出版本、文件与哈希；不复制任务数据库 |

首版如果按 Bundle 而非视频建目录，应如实标注 Bundle 导出范围；目录呈现完成不等于已经实现每视频的采集与合并。

### 3.4 普通使用顺序

用户打开导出目录，进入课程总览，阅读全文和本地图，在个人笔记中写下问题或行动项，再按需要回到原视频核对。后续补齐资料时，程序刷新机器整理内容并保留个人笔记。断网后，已经导出的文字和图片仍应可读；回看原视频则需要有效登录和网络。

## 4. 与后端单一台账的关系

SQLite 和已发布 Bundle 继续保存采集、发布、阅读、分析与补采的业务状态。Vault 是可重新生成的阅读材料及用户自己的笔记，不登记第二套“任务已经成功”。

导出成功只表示目标文件已经可靠生成，不表示：

- 百度网盘采集通道已经跑通。
- 文稿覆盖了全部语音且识别无误。
- 所有关键操作都有截图。
- Agent 真正消费过图像字节或完成分析。
- 用户已经读完或学完课程。

用户的学习状态可以独立记录，但不能把 Obsidian 中手工勾选的“已学完”当成后端的“证据已齐”。后续若支持修订转写，应建立有来源的校订版本，保留原始转写，而不是直接覆盖原始证据。

## 5. 属性、身份与链接

### 5.1 Properties 只放简明字段

Obsidian 属性存于 Markdown 顶部 YAML，支持文本、数字、日期、列表等；属性 UI 不支持嵌套结构，也不渲染属性值中的 Markdown。复杂分段、图像证据和校验结果应继续保留在现有 manifest，展示页只放少量平面字段。

依据：[Properties](https://help.obsidian.md/Editing+and+formatting/Properties)。

可选属性示例，**以下并非真实采集结果，也不是首版字段合同**：

```yaml
---
wa_type: video_material
wa_video_id: "稳定视频标识"
wa_course_id: "稳定课程标识"
wa_revision: "已发布版本"
title: "课程第 1 节"
duration_seconds: 1200
transcript_status: partial
frames_status: needs_review
---
```

若导出单位是 Bundle，应使用真实的 Bundle ID、版本和状态，不伪造视频 ID 或课程时长。后续资料桥接应把平台字幕、平台文稿、平台笔记、平台附图、源视频帧、OCR 与 AI 分析分开标识。

### 5.2 身份与文件名分开

业务身份应绑定稳定源 ID 和证据版本。标题、网页地址和本地路径可能变化，不适合作唯一身份。文件名使用安全名称；相同图片可去重存储，但图片在不同视频或时间点的出现记录不能随之消失。

Obsidian 能在重命名文件时更新内部链接，但不能自动更新 Worldanalysis 的外部索引。后续若支持用户改名与移动，需要按笔记身份发现新路径；出现多个相同 ID 时保留冲突，不猜测。首版未实现该能力时，文档应明确固定导出目录的支持边界。

依据：[Internal links](https://help.obsidian.md/links)。

### 5.3 时间戳链接必须诚实

正文应保留可读的时间值；机器记录的时间单位需明确。链接指向真实原视频页面，而不是临时带签名媒体直链。Cookie、访问令牌和临时授权头不得写入可以分享的笔记。

把 `#t=` 附到一个网址上不能证明目标播放器支持跳转。没有经过播放器适配验证时，写明“打开原视频；对应时间 00:12:34”，不要宣称点时间必定跳到该位置。精准跳转是单独的播放器能力。

## 6. 人工编辑与增量更新

### 6.1 首版保护原则

程序写入前应识别自己此前生成的文件，记录上次生成哈希，并比较当前内容。用户修改过程序管理文件时，保留当前文件，输出待合并版本或冲突说明，不能静默覆盖。已有未知文件不可仅因名字相同就接管。

个人笔记应采用“仅不存在时创建”的策略。导出重复运行不应增加重复条目或图片，也不应重置用户标签、批注或已整理的布局。

先提供明确的机器资料和个人笔记边界，后续再按真实需要做双向编辑。不要以 HTML 标记存在为唯一依据，认为标记以内的人为修订可以无条件删除。

### 6.2 写入过程与冲突

外部导出器需要单写者、旧版本检查和原子发布策略，避免展示半写文件。若将来开发 Obsidian 插件，官方建议使用 `Vault.process()` 处理基于当前文本的读改写；异步操作完成后还要检查文本是否已变化。

依据：[Vault API](https://docs.obsidian.md/Plugins/Vault)。

`Vault.process()` 的能力不能扩大为外部 Python 进程与 Obsidian 之间的全局锁。实际导出器必须明确自己提供的并发保护范围，不能据文档宣称所有并发编辑已经安全。

## 7. Bases 与 Canvas 的使用顺序

### 7.1 Bases：可选资料表格

Bases 是 Obsidian 核心插件，直接以 Markdown 与属性作为数据，可保存表格、卡片等视图。可以提供“全部资料”和“仍有缺口”两种视图，避免自建第二套课程后台。未启用 Bases 时，普通课程总览仍应完整可用。

依据：[Introduction to Bases](https://help.obsidian.md/bases)、[Bases syntax](https://help.obsidian.md/bases/syntax)。

建议的首个视图仅列标题、时长、文字状态和画面状态。`.base` 是视图配置，不是权威任务状态；不要靠修改视图内属性来宣告证据已完成。此配置属于可选后续增强，不能在没有生成和实测时列作首版已交付功能。

### 7.2 Canvas：用户整理关系

Canvas 能直接排列笔记、附件与网页，使用开放 JSON Canvas 格式。课程关系整理可引用已有笔记与图片，Worldanalysis 无需再开发节点编辑器。

依据：[Canvas](https://help.obsidian.md/Plugins/Canvas)、[JSON Canvas 规范](https://jsoncanvas.org/spec/1.0/)。

优先使用文件卡片引用资料，不把整段全文复制进文字卡片。官方说明文字卡片不进入反向链接，需要转换为文件才出现。用户修改后的坐标、连线与分组应保留，更新文稿不能重置其布局。

## 8. 何时需要采集桥或薄插件

本地阅读、检索和个人笔记都不需要 Web Viewer。以下能力才需要额外桥接：

- 从已登录百度页面读取平台字幕、文稿或笔记图片。
- 在 Obsidian 内打开原视频并精确定位时间。
- 保存当前实际播放画面并绑定正确视频身份。
- 从 Obsidian 触发后端的补采任务并查看结果。

Web Viewer 是桌面核心插件，允许在 Obsidian 中打开网页标签、分栏和弹出窗口，但它不会自动完成百度适配，也不保证页面采集稳定。

依据：[Web viewer](https://help.obsidian.md/plugins/web-viewer)。

可以参考 Tyukeying 导入器的字幕发现、笔记 HTML 转换、图片保存和视频身份关联设计。复用时仍须补齐全文验收、批量组合流程、缺图状态及原帧区分。采集桥将结果交给 Worldanalysis 的已有证据合同，由后端发布后再导出 Vault；不让插件自己维护另一套成功台账。

参考：[Baidu Course Notes Importer](https://github.com/Tyukeying/baidu-course-notes-importer)。

## 9. 首批验收与未验证事项

| 用户路径 | 应核对的结果 | 证据性质 |
| --- | --- | --- |
| 导出一个已发布 Bundle | 文字、图片、身份与缺口对应真实 Bundle，原证据不变 | 可做本地功能验证 |
| 重复导出 | 不重复条目，不覆写个人笔记 | 可做本地功能验证 |
| 目标存在未知文件或用户编辑 | 明确保留冲突，不静默覆盖 | 必要数据保护验证 |
| 中途写入失败 | 单个文件完整写入；整批文件不是一次事务切换，不把未发布结果当成功 | 必要发布验证 |
| 用 Obsidian 打开目录 | 无第三方插件也能阅读图片与文字，链接可用 | 需真实 UI 验证 |
| 断网查看已有资料 | 本地文字与图像可读，回看来源如实依赖网络 | 需真实 UI 验证 |
| 原视频链接过期 | 本地内容保留，不能把链接失败当资料消失 | 后续来源恢复验证 |
| 用户重命名或移动资料 | 按 ID 追踪或明确提示未支持，不生成同源重复条目 | 后续能力验证 |
| 从百度直接采集课程 | 全文、真实帧、正确身份、缺口与全过程媒体落盘边界通过 | 独立真实采集验收 |
| 交给分析 Agent | 文本、图片真实消费与引用合规，状态不因导出而改变 | 既有分析验收 |

文档模板、可打开的演示 Vault 和本地功能测试都不能代替真实网盘课程验收。先完成可读材料出口，再以实际课程验证采集桥与媒体补缺，才能把完整流程判为交付。
