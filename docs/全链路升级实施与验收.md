# Worldanalysis 实施与验收

## 运行入口

- 用[资源库运行指南](../_ingest/wangzjk-to-pan/v4-review/README.md)启动本机服务，依次核对资源库、课程表和控制台。站点索引和任务记录由部署环境提供。
- 用[专用 DSH 手册](专用DSH运行与接管.md)检查专用工作区、授权、调度归属和回执。切换执行入口须先在本机验明身份和任务范围。
- 在正式课程工作树调用 `_tools/course_production/course.ps1`。原件、正式批次和测试库的路径由部署环境提供。详细步骤见[课程制作手册](<课程资料整理与 Obsidian 教材制作手册.md>)。

## 业务验收

1. 在资源库或课程表用实际数据选择确切项目与版本，核对顺序和网页状态。转存和分析清单分别确认。桌面和窄屏各走一遍同一操作路径。
2. 专用 DSH 依现有授权核实目标、账户、范围、结果及实际收件。验证暂停时保留断点。对应状态以已确认回执和实物为准。
3. 正式分析读取收到范围，按身份和版本登记。先从原件提取教学要点，再映射至同段正文、关键图及必要实物。同源或历史补件沿同一入口续作。
4. 指定测试 Agent 对照原件独立查漏和核实事实，走查步骤及原格式资料。隔离 Obsidian 重开当前同版正文，逐篇阅读 Markdown 配套并核查关键链接。已签收教材按原版本的有效回执读回。
5. 将教材、范围状态、同版回执和批次登记对齐，再验网页反馈。只有完成保全及当次授权的对象才进入相应的清理预检和执行。

## 发布与恢复

- 改动在隔离目录复验，保存旧行为、负例、实际样本的范围及当前版本。生产部署需在目标主机重启或加载版本后重新读回。源码回归、现场显示和完整业务验收分别记录。
- 遇到失败先保留现场，检查同一版本、账号、对象与证据。发布失败沿旧有效签收继续阅读，外部副作用未知时先查已有结果。
- GitHub 提交通用代码、规则、手册和测试。部署配置、会话身份、分享信息、课程资料、运行台账和验收回执留在本机。
